# TinyHAR Reproduction and Extension — COMP8240

This repository is a reproducibility and extension project based on the authors' public implementation of:

> Yexu Zhou, Haibin Zhao, Yiran Huang, Michael Hefenbrock, Till Riedel, and Michael Beigl.  
> **TinyHAR: A Lightweight Deep Learning Model Designed for Human Activity Recognition.**  
> ISWC 2022, Best Paper Award.  
> https://doi.org/10.1145/3544794.3558467

Upstream repository: https://github.com/teco-kit/ISWC22-HAR

The original TinyHAR source code is retained where possible. The `scripts/` and `results/` directories contain the additional reproducibility, robustness, and SIDDHA experiments developed for the COMP8240 project.

## Project scope

The project contains three main experimental components:

1. **WISDM replication** — run TinyHAR on the original WISDM v1.1 data and investigate differences between the released configuration and the published model.
2. **Constructed WISDM robustness data** — evaluate the same trained TinyHAR checkpoint under controlled Gaussian noise, missing samples, channel dropout, and reduced sampling frequency.
3. **SIDDHA transfer experiment** — adapt the paper-aligned TinyHAR architecture to an external 18-class HAR dataset using subject-independent train/validation/test splits.

The released repository configuration produces 25,028 trainable parameters for WISDM. The paper reports 16,184. The project therefore also includes a **paper-aligned 16-filter TinyHAR configuration**, which reproduces the published parameter count exactly.

## Reproducing the WISDM experiment

### 1. Inspect the released TinyHAR/WISDM pipeline

```bash
python scripts/run_wisdm_tinyhar.py
```

This uses the released model configuration and exposes the parameter-count discrepancy between the repository configuration and the paper.

### 2. Train the paper-aligned WISDM Fold 1 model

```bash
python scripts/train_wisdm_tinyhar_fold1.py
```

The script:

- uses random seed 1;
- uses the first grouped subject fold from the released loader;
- holds out subjects 1, 2, 3, and 4;
- constructs TinyHAR with `filter_num=16`;
- checks that the model contains exactly 16,184 trainable parameters;
- trains for 10 epochs using Adam with learning rate 0.001;
- selects the checkpoint with minimum validation loss.

Training metrics are saved to:

```text
results/assessment2_wisdm_fold1/metrics.csv
```

The current training script also writes final held-out metrics to:

```text
results/assessment2_wisdm_fold1/test_metrics.csv
```

The trained checkpoint is created locally at:

```text
results/assessment2_wisdm_fold1/best_model.pth
```

The checkpoint is deliberately excluded by `.gitignore`. It must be regenerated by running the training command above before the robustness experiment.

The held-out Fold 1 result obtained for the report was:

- Accuracy: 86.34%
- Weighted F1: 86.84%
- Macro-F1: 78.75%

## WISDM robustness experiment

After the Fold 1 checkpoint has been generated, run:

```bash
python scripts/evaluate_wisdm_perturbations.py
```

Then generate the summary plot with:

```bash
python scripts/plot_wisdm_robustness.py
```

Outputs are stored under:

```text
results/constructed_wisdm_perturbations/
```

Important files include:

- `summary.csv`
- `manifest.csv`
- `per_class_f1.csv`
- `robustness_macro_f1.png`

The perturbations are applied only to held-out test windows. The model is not retrained on degraded data.

## SIDDHA experiment

### 1. Inspect the source dataset

```bash
python scripts/inspect_siddha.py
python scripts/check_siddha_sessions.py
```

### 2. Construct five-second smartphone accelerometer windows

```bash
python scripts/prepare_siddha_windows.py
```

This selects phone accelerometer X/Y/Z, uses 100-sample windows at 20 Hz, and applies a stride of 50 samples (50% overlap). Windows are constructed within each subject/activity session so that they cannot cross subject or activity boundaries.

### 3. Construct the subject-independent split

```bash
python scripts/prepare_siddha_subject_split.py
```

This creates a deterministic seed-1 split with:

- 41 training subjects;
- 5 validation subjects;
- 5 test subjects.

The script checks that the subject sets are disjoint and calculates normalization statistics from training subjects only.

### 4. Train TinyHAR on SIDDHA

```bash
python scripts/train_siddha_tinyhar.py
```

The SIDDHA experiment uses the 16-filter TinyHAR architecture with an 18-class prediction head. The model contains 16,580 trainable parameters.

Training outputs are stored under:

```text
results/assessment2_siddha/
```

The held-out result used in the report was:

- Accuracy: 36.02%
- Macro-F1: 33.17%
- Weighted F1: 33.17%

### 5. Analyse held-out predictions

```bash
python scripts/analyze_siddha_test.py
python scripts/plot_siddha_training.py
```

Outputs include:

- `metrics.csv`
- `siddha_per_class_f1.csv`
- `siddha_confusion_matrix.png`
- `siddha_test_predictions.csv` when generated locally
- deterministic error samples used for the LLM-as-judge analysis

## Manual LLM-as-judge

The complete manual evaluation protocol and saved ratings are in:

```text
results/assessment2_siddha/llm_judge_protocol.md
results/assessment2_siddha/siddha_llm_judge_results.csv
```

Thirty misclassified held-out SIDDHA windows were selected deterministically with:

```python
errors.sample(n=30, random_state=2026)
```

The judge received only the true and predicted activity labels. Raw sensor data, subject metadata, and confidence scores were not supplied.

## Reproducibility notes

- Source datasets are not committed because of their size.
- Trained `.pth` checkpoints are not committed and must be regenerated.
- WISDM Fold 1 uses the grouped subject split defined by the released loader; it is subject-independent but is not literal leave-one-subject-out cross-validation.
- The released loader uses 50% window displacement for training windows and 10% displacement for test windows.
- Within each WISDM training fold, the released loader shuffles training windows and uses a window-level 90/10 train/validation split; validation subjects therefore overlap with training subjects.
- SIDDHA uses subject-disjoint train, validation, and test sets and training-only normalization.
